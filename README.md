# docs-chat

検索・RAG・ベクトル DB・SSE を、小さな RAG チャットボットを TypeScript で作りながら学ぶためのリポジトリ。

最初はフレームワーク（LangChain・Vercel AI SDK など）を使わずに素の実装で仕組みを理解し、そのあとでライブラリに置き換えて「何を肩代わりしてくれているか」を確かめる。

## 進め方（目安 4〜6 週間）

| 週   | やること                                                                                                                 | 読むもの                                               |
| ---- | ------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------ |
| 0    | `data/docs/` に検索対象の文書（マークダウン数十ファイル）を置く                                                          | 『コンテキストエンジニアリング』第 1 章                |
| 1    | 転置インデックスと **BM25** によるキーワード検索を自分で実装する（日本語の分割は `Intl.Segmenter` か bigram）            | 『検索システム』の転置インデックス・テキスト解析の章   |
| 2    | embedding を作って **pgvector**（Docker）に入れ、ベクトル検索をする。BM25 と結果を比べ、両方を混ぜる（ハイブリッド検索） | pgvector の README、Anthropic「Contextual Retrieval」  |
| 3    | 検索結果を LLM に渡し、**参照元つきで回答**させる（ここで RAG が完成）                                                   | 『コンテキストエンジニアリング』の RAG の章            |
| 4    | 回答を **SSE で手書き**してブラウザに少しずつ表示する。そのあと Vercel AI SDK に置き換えて比べる                         | MDN「Using server-sent events」                        |
| 5〜6 | 質問と正解を 20 問作って**評価**し、チャンクのサイズや検索方法を変えて正答率を上げる                                     | 『コンテキストエンジニアリング』、RAGAS のドキュメント |

LLM や embedding の提供元、DB の構成は、その週になったときに決める（先に決めない）。

毎週、[学習記録](docs/learning-log.md)に「何を変えたら、何がどれだけ良くなったか」を 1 行で残す。

## 開発

```sh
pnpm install
pnpm test        # Vitest
pnpm lint        # oxlint
pnpm format      # oxfmt
pnpm typecheck   # tsc
```

CI（GitHub Actions）で lint・format・typecheck・test を実行する。
